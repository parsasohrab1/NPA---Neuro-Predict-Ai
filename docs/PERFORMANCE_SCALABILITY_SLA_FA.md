## کارایی، مقیاس‌پذیری، دسترس‌پذیری (SLA/SLO/SLI)

### اهداف کارایی (Latency & Throughput)
- CRUDهای معمول (Patients/Records/Products):
  - Latency: p50 ≤ 200ms، p95 ≤ 600ms، p99 ≤ 1s
  - Throughput: حداقل 300 درخواست/دقیقه در مقیاس پایه
- آپلود تصویر (MRI/DICOM) تک‌فایل:
  - Latency بارگذاری: وابسته به اندازه؛ اعتبارسنجی اولیه ≤ 2s برای فایل‌های ≤ 100MB
  - مسیرهای پردازش آسنکرون در فازهای بعد برای فایل‌های حجیم
- اجرای پیش‌بینی:
  - Latency همگام (MVP): ≤ 2s برای مدل پایه و ورودی استاندارد
  - در صورت طولانی‌شدن، صف آسنکرون و Polling/Webhook در فازهای بعد

اقدامات پشتیبان:
- کش نتایج خواندنی پرتکرار با TTL (۵–۱۰ دقیقه) و بی‌اعتبارسازی هدفمند
- Eager loading برای جلوگیری از N+1 در کوئری‌ها
- شاخص‌گذاری پایگاه داده روی کلیدهای جستجوی پرتکرار


### مقیاس‌پذیری (Scalability)
- معماری مبتنی بر سرویس‌های سبک و stateless برای API؛ قابلیت افزایش replica
- جداسازی مسیرهای سنگین (آپلود/پیش‌بینی) و استفاده از صف/کارگر در فازهای بعد
- استفاده از Redis برای کش/Rate Limit و کانال‌های آسنکرون
- ذخیره‌سازی فایل در دیسک/شی‌ء-استور با امکان گسترش افقی
- استراتژی Read/Write Split در پایگاه‌داده (فازهای بعد) و Sharding در صورت نیاز

ظرفیت‌گذاری اولیه:
- 2–3 replica برای API (HPA بر مبنای CPU/Latency)
- منابع مستقل برای پردازش تصویر/مدل در صورت نیاز (GPU در فازهای بعد)


### دسترس‌پذیری و مقادیر هدف (SLA/SLO/SLI)
- SLA (هدف بیرونی MVP): Uptime ≥ 99.5% ماهانه
- SLO (اهداف داخلی):
  - Uptime ≥ 99.7% برای API
  - Latency هدف: p95 ≤ 600ms روی مسیرهای CRUD
  - Error Rate ≤ 1% (۵xx/۴xx بحرانی) ماهانه
  - زمان بازیابی میانگین (MTTR) ≤ 30 دقیقه برای رخدادهای سطح 2
- SLI (شاخص‌های قابل‌سنجش):
  - Availability: نسبت درخواست‌های موفق (2xx/3xx) به کل
  - Latency: p50/p95/p99 به تفکیک مسیر
  - Error Rate: درصد 5xx و 4xx بحرانی
  - Saturation: CPU/Memory/DB connections/Queue depth


### پایش و هشداردهی (Observability)
- لاگ ساختاریافته با Request ID و Correlation ID
- متریک‌های سیستم و اپلیکیشن (Prometheus/Grafana): Latency، Error Rate، Uptime، Resource usage
- Alerting:
  - p95 Latency > هدف به مدت 5 دقیقه
  - Error Rate > 2% به مدت 5 دقیقه
  - Uptime < SLO در بازه روزانه
  - saturation بالای 80% منابع حیاتی


### استراتژی‌های تاب‌آوری (Resilience)
- Timeouts، Retry با Backoff و Circuit Breaker برای وابستگی‌ها
- طراحی Fail-Fast و مسیرهای Degraded (بازگشت پاسخ کش) در قطعی‌های موقت
- Idempotency برای عملیات‌های حساس (آپلود/پرداخت/پیش‌بینی همگام)


### مسیر بهبود تدریجی
- فاز 1 (MVP): کش، ایندکس‌ها، Eager loading، HPA ساده، مانیتورینگ پایه
- فاز 2: صف آسنکرون برای پیش‌بینی/پردازش تصویر، بهینه‌سازی DB، Replica API بیشتر
- فاز 3: Read/Write Split، CDN/شیء-استور، استقرار بدون وقفه، Fine-grained SLOها
