# 📋 نیازمندی‌ها و طراحی UX داشبورد ادمین NeuroPredict-AI

این سند نیازمندی‌های سطح بالا، نقش‌های هدف و طرح کلی تجربه کاربری داشبورد ادمین را برای توسعه و ارزیابی در اختیار تیم قرار می‌دهد.

---

## 👤 نقش‌های هدف

### مدیر سیستم (System Admin)
- مدیریت کاربران، نقش‌ها و سیاست‌های امنیتی
- نظارت بر وضعیت سرویس‌ها و سلامت زیرساخت
- پیکربندی تنظیمات سیستم، اعلان‌ها و نسخه‌های نرم‌افزار

### مهندس DevOps / SRE
- پایش منابع (CPU, RAM, Storage)، صف‌های پردازش و سرویس‌های حیاتی
- مدیریت رخدادها و مشاهده لاگ‌های سیستمی و امنیتی
- هماهنگی با تیم‌ها برای پاسخ سریع به خطاها و بازیابی سرویس

### دانشمند داده / ML Engineer
- مشاهده نسخه‌های مدل، متریک‌های عملکرد، وضعیت استقرار
- مدیریت فرآیند آپلود و انتشار مدل‌های جدید
- تحلیل drift داده/مفهوم و بررسی هشدارهای مرتبط با کیفیت مدل

> **نکته:** هر سه نقش از یک هسته اطلاعاتی مشترک استفاده می‌کنند اما سطح دسترسی و تمرکز آن‌ها متفاوت است. UI باید اجازه دهد اپراتور با نقش مناسب سریعاً به بخش مربوطه برسد.

## 🧩 بخش‌های اصلی داشبورد

1. **System Monitoring**
   - نمای کلی منابع، سرویس‌ها و صف‌ها
   - هشدارهای فعال و تاریخچه رویدادهای بحرانی
   - Drill-down برای مشاهده جزئیات (instances, containers, services)

2. **User & Role Management**
   - لیست کاربران با فیلتر و جستجو
   - ساخت/ویرایش کاربر، تخصیص نقش و دسترسی
   - سیاست‌های امنیتی (فعال‌سازی MFA، قفل حساب، تنظیم رمز)

3. **Model Management**
   - لیست نسخه‌های مدل و وضعیت استقرار (Production, Staging, Retired)
   - متریک‌های عملکرد (Accuracy, Precision, Recall, AUC, Latency)
   - عملیات روی مدل (آپلود، فعال‌سازی، rollback، تست آفلاین)
   - هشدارهای drift و توصیه‌های اقدامات اصلاحی

4. **Audit Logs**
   - جدول رویدادها با فیلتر (کاربر، نوع رویداد، سطح اهمیت، بازه زمانی)
   - جزئیات هر رویداد (payload، IP، سرویس درگیر، نتیجه)
   - امکان export و پین‌کردن رویدادهای کلیدی

5. **System Settings**
   - پیکربندی امنیتی (سیاست رمز، IP whitelist، session timeout)
   - تنظیمات مدل (آستانه ریسک، confidence minima، alert thresholds)
   - تنظیمات اعلان‌ها (ایمیل، SMS، وب‌هوک)
   - مدیریت پشتیبان‌گیری و بازیابی

## 🧭 فلوهای کلیدی کاربر

### A. پاسخ به هشدار بحرانی (System Admin / DevOps)
1. ورود به داشبورد → مشاهده کارت Summary در System Monitoring
2. کلیک روی هشدار فعال → باز شدن drawer با جزئیات
3. مشاهده متریک‌های مرتبط و آخرین تغییرات
4. اقدام سریع (مثلاً restart سرویس، ساخت Incident، اطلاع‌رسانی)

### B. افزودن کاربر جدید (System Admin)
1. ورود به بخش User & Role Management
2. انتخاب «ایجاد کاربر» → فرم با فیلدهای الزامی و نقش‌ها
3. فعال‌سازی MFA و تعیین سیاست رمز
4. ذخیره → ثبت در audit log و ارسال دعوت‌نامه ایمیلی

### C. انتشار مدل جدید (Data Scientist)
1. مراجعه به Model Management → تب «نسخه‌ها»
2. آپلود فایل مدل + متادیتا (توضیحات، commit، متریک‌های پیش‌دستی)
3. اجرای تست آفلاین در محیط staging (دکمه «Validate»)
4. فعال‌سازی مدل → انتخاب محیط Production → تعیین تاریخ فعال‌سازی
5. ثبت نتیجه و مانیتورینگ متریک‌های پس از انتشار

## ✅ پذیرش و معیارهای موفقیت
- نقش‌های تعریف‌شده بتوانند بدون سردرگمی به بخش‌های مورد نیاز دسترسی پیدا کنند.
- اطلاعات حیاتی (هشدارها، وضعیت مدل، تغییرات امنیتی) در کمتر از دو کلیک در دسترس باشد.
- هر اقدام حساس (تغییر تنظیمات، انتشار مدل، مدیریت کاربر) از مسیر مشخص با تایید صریح و ثبت در لاگ انجام شود.
- طرح وایرفریم به عنوان مرجع برای طراحی بصری (Figma یا معادل) مورد استفاده قرار گیرد.

## 🔄 گام‌های بعدی پیشنهادی
1. تأیید نیازمندی‌ها توسط ذینفعان (DevOps، تیم پزشکی، مدیریت).
2. تبدیل وایرفریم متنی به طرح بصری (Figma).
3. تعریف APIهای موردنیاز و تفکیک تیکت‌های توسعه (Frontend/Backend).
4. تدوین چک‌لیست UX/UI بر اساس این مستند برای بازبینی در طول پیاده‌سازی.
