## گردش‌کارها، وضعیت‌ها و قوانین اعتبارسنجی


### 1) گردش‌کار ثبت بیمار و سوابق
- ایجاد بیمار → تخصیص پزشک → ثبت سوابق اولیه → مشاهده در داشبورد
- استثناها: شناسه بیمار تکراری، داده‌های ناقص، نقش غیرمجاز

وضعیت‌های مرتبط:
- بیمار: active / inactive
- رکورد پزشکی: created → updated (حذف واقعی فقط برای ادمین)

اعتبارسنجی‌ها (نمونه):
- patient_id یکتا و غیرخالی
- first_name/last_name اجباری، تاریخ تولد معتبر و کوچکتر از امروز
- gender از مقادیر مجاز
- طول فیلدها و قالب ایمیل/تلفن مطابق استاندارد


### 2) گردش‌کار آپلود تصویربرداری (Imaging)
- انتخاب بیمار → آپلود MRI/DICOM → اعتبارسنجی فرمت/حجم → لینک‌کردن به رکورد → آماده برای تحلیل
- خطاها: فرمت نامعتبر، حجم بیش از حد، عدم انطباق متادیتا، ارتباط‌نداشتن با بیمار

وضعیت‌های مرتبط (برای هر مطالعه تصویربرداری):
- uploaded → validating → processed | failed
- processed → linked_to_record

اعتبارسنجی‌ها:
- فقط پسوند/فرمت مجاز (DICOM/MRI)؛ محدودیت حجم فایل
- وجود patient_id معتبر و دسترسی نقش `nurse`+ برای آپلود
- ذخیره متادیتا ضروری (اندازه، modality، زمان)


### 3) گردش‌کار پیش‌بینی (Predictions)
- انتخاب بیمار با رکورد اخیر → اجرای مدل → ذخیره خروجی ریسک/اعتماد → تولید گزارش
- خطاها: نبود رکورد بالینی اخیر، نقش غیرمجاز، خطای مدل/منابع

وضعیت‌های مرتبط (پیش‌بینی):
- pending → running → completed | failed
- completed → reviewed (در صورت مرور پزشک)

اعتبارسنجی‌ها:
- نقش `doctor`+ برای ایجاد پیش‌بینی
- وجود حداقل یک رکورد پزشکی معتبر برای بیمار
- محدوده مقادیر خروجی مدل: [0,1] برای ریسک/اعتماد


### 4) گردش‌کار گزارش (Reports)
- تولید گزارش از آخرین پیش‌بینی/سوابق → ذخیره PDF → دانلود/پرینت
- خطاها: نبود پیش‌بینی معتبر، قالب خروجی نامعتبر

وضعیت‌های مرتبط (گزارش طولی - در فازهای بعد):
- scheduled → running → succeeded | failed

اعتبارسنجی‌ها:
- دسترسی `viewer`+ برای مشاهده/دانلود
- صحت لینک فایل و وجود مجوزهای لازم


### 5) گردش‌کار طولی (Longitudinal)
- ایجاد Episode → ثبت Visitهای دوره‌ای → مقایسه روند → (فاز بعد) هشدارها

وضعیت‌های مرتبط:
- Episode: open → closed
- Visit: created → updated
- Alert (فاز بعد): new → acknowledged → resolved

اعتبارسنجی‌ها:
- نقش `nurse`+ برای ایجاد/ویرایش Episode/Visit
- تاریخ و ترتیب زمانی معتبر، کامل‌بودن شاخص‌های ضروری


### 6) مدیریت محصول/مدل (Product/Model)
- ثبت/ویرایش مشخصات محصول → فعال/غیرفعال → استفاده در سیستم

وضعیت‌های مرتبط:
- Product: active / inactive
- Model (فاز بعد): staged → active → deprecated

اعتبارسنجی‌ها:
- نقش `admin` برای Create/Update/Delete
- نام و نسخه غیرخالی، `specs` و `metadata` با ساختار JSON معتبر


## قوانین اعتبارسنجی عمومی
- احراز هویت برای همهٔ مسیرها به‌جز Login/Health
- کنترل دسترسی بر اساس نقش‌ها (RBAC)
- محدودیت اندازه/نوع فایل برای آپلود
- بررسی یکتایی مقادیر کلیدی (شناسه بیمار و ...)
- بازه‌های عددی معتبر (مثلاً 0 ≤ score ≤ 1)
- تاریخ‌ها معتبر و سازگار (تولد < امروز، ترتیب Visits)
- ورودی‌های متنی با طول مجاز؛ ضدعفونی ورودی‌ها
- کش نتایج خواندنی پرتکرار با TTL و بی‌اعتبارسازی هدفمند


## قوانین خطا و بازیابی
- پیام‌های خطای استاندارد با کد وضعیت مناسب (400/401/403/404/409/500)
- ثبت لاگ برای رخدادهای کلیدی و خطاها (قابل ممیزی)
- سیاست تلاش مجدد برای عملیات وابسته به شبکه (در لایه سرویس)
- اتمیک‌بودن تراکنش‌های نوشتاری در پایگاه داده


## شبه‌ماشین حالت‌ها (نمونه‌های کلیدی)
- Imaging: uploaded → validating → (processed | failed) → linked_to_record
- Prediction: pending → running → (completed | failed) → reviewed
- Longitudinal Episode: open → closed
- Report Job (فاز بعد): scheduled → running → (succeeded | failed)
