## رودمپ، اولویت‌بندی، و شکستن فیچرها به استوری

### چشم‌انداز نسخه‌ها (High-level Roadmap)
- فاز 1 (MVP – 6 تا 8 هفته)
  - بیماران/سوابق پایه (CRUD)، آپلود DICOM، پیش‌بینی پایه، گزارش PDF ساده
  - داشبورد کلینیکی ساده، RBAC پایه، مانیتورینگ سلامت، ریت‌لیمیت اولیه
- فاز 2 (8 تا 12 هفته بعد)
  - طولی (Episode/Visit) و نمودار روند، گزارش‌های بهبود‌یافته
  - یکپارچگی یک‌طرفه HIS/PACS (Pull)، داشبورد مدیریتی عملیاتی
  - متریک‌ها/هشدارها (Prom/Grafana)، بهینه‌سازی کارایی و کش
- فاز 3 (12 تا 16 هفته بعد)
  - هشدارهای طولی، Explainability بیشتر، زمان‌بندی گزارش‌ها
  - امنیت پیشرفته (MFA، IP Whitelist)، تریسینگ (OTel)
  - صف آسنکرون برای پردازش‌ها، بهبود استقرار (Canary/Blue-Green)
- فاز 4 (پس از پایداری)
  - یکپارچگی دوطرفه، مدیریت نسخه مدل/Drift، بهینه‌سازی هزینه


### چارچوب اولویت‌بندی (Value/Effort + Risk)
- ارزش (Value): اثر بر نتایج بالینی/کاربر، کاهش زمان تشخیص (TTR)، بهبود پذیرش محصول
- هزینه/تلاش (Effort): پیچیدگی فنی/تیم، نیاز به تغییرات دیتابیس/زیرساخت
- ریسک: امنیت/انطباق، اثر جانبی بر بخش‌های حساس، وابستگی‌های خارجی
- ماتریس اولویت (سریع): High-Value/Low-Effort → ابتدا؛ High-Risk → برنامه کاهش ریسک/پایلوت


### الگوی شکستن فیچرها (Epics → Features → User Stories → Tasks)
- Epic: واحد بزرگ معنی‌دار (مثلاً «پیگیری طولی»)
- Feature: زیرقابلیت قابل ارائه (مثلاً «ساخت Episode/Visit»، «نمودار روند»)
- User Story (فرمت): «به‌عنوان [نقش]، می‌خواهم [هدف] تا [ارزش].»
  - معیار پذیرش (Acceptance Criteria) روشن، سناریوهای موفق/خطا، RBAC و عملکرد
- Tasks: کارهای مهندسی کوچک (backend/frontend/tests/devops/docs)


### نمونه‌ها (خلاصه)
- Epic: «پیش‌بینی پایه و گزارش»
  - Feature: «اجرای پیش‌بینی آلزایمر/پارکینسون»
    - Story: «به‌عنوان پزشک، می‌خواهم برای بیمار با آخرین رکورد، پیش‌بینی ریسک را اجرا کنم تا تصمیم‌گیری درمانی سریع‌تر شود.»
      - Acceptance:
        - RBAC: نقش doctor+
        - ورودی معتبر: وجود حداقل یک MedicalRecord
        - خروجی: ریسک‌ها/اعتماد در [0,1] و ذخیره در DB
        - زمان پاسخ ≤ 2s (MVP)
        - تست‌های واحد/یکپارچه + گزارش PDF قابل دانلود
      - Tasks: API POST /predictions، سرویس مدل، schema و تست، PDF ساده

- Epic: «طولی و هشدارها»
  - Feature: «Episode/Visit CRUD + نمودار روند»
    - Story: «به‌عنوان پزشک، می‌خواهم روند نمرات شناختی بیمار را در بازه زمانی ببینم تا تغییرات معنادار را پیگیری کنم.»
      - Acceptance: فیلتر بازه، نمودار با برچسب/توضیحات، RBAC nurse+/doctor+، بارگذاری ≤ 600ms p95
      - Tasks: مدل/اسکیما/API، کوئری‌های بهینه، UI نمودار، تست‌های Integration


### DoR/DoD برای استوری‌ها
- DoR: نیازمندی شفاف/قابل‌تست، RBAC مشخص، اثر DB/ایندکس معلوم، معیار عملکرد تعیین‌شده
- DoD: lint/test/SAST ok، پوشش ≥ 60% (ابتدایی)، عدم N+1، مستند و قابل دمو، لاگ/متریک اضافه‌شده


### راهنمای زمان‌بندی اسپرینت (دو هفته‌ای - نمونه)
- هفته 1: تحلیل/طراحی سبک، پیاده‌سازی Backend و تست‌های واحد/یکپارچه، اسکلت UI
- هفته 2: تکمیل UI و تست‌های E2E منتخب، سخت‌کردن امنیت/هدرها/CSP Report-Only، دمو و بازخورد


### شاخص‌های پیگیری رودمپ
- تحویل فیچرها در موعد، کیفیت (نرخ باگ/رگرسیون)، SLOها (Latency/Error/Uptime)
- پذیرش کاربر (MAU، نرخ تکمیل گزارش/پیش‌بینی)، بازخورد CSAT/NPS
- هزینه/ظرفیت: مصرف منابع، زمان‌های صف/صفحه‌بندی، هزینه هر پیش‌بینی/گزارش
