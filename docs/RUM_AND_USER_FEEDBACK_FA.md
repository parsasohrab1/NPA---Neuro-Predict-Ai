## برنامه رصد تجربه کاربر (RUM) و بازخورد (Feedback)

### اهداف
- سنجش تجربه واقعی کاربر (Frontend/Backend) و بستن حلقه بازخورد برای بهبود مستمر UX/کارایی.


### شاخص‌ها (RUM Metrics)
- Core Web Vitals: LCP، CLS، INP/TTI
- عملکرد ادراکی: FCP، TTFB
- پایداری: نرخ خطای کلاینت (JS errors)، خطاهای API (۴xx/۵xx)، نرخ Timeout/Retry
- کاربردپذیری: نرخ تکمیل فرم‌ها، زمان کار تکلیف (Task Time)، نرخ رهاسازی (Drop-off)
- قابلیت مشاهده: درصد کاربران با تجربه «خوب»/«نیاز به بهبود»


### جمع‌آوری داده (Privacy-first)
- روش‌ها:
  - RUM سبک در کلاینت (listenerهای Web Vitals و عملکرد) بدون PII/PHI
  - شمارش خطاهای JS با Stack مختصر (حذف/ماسک مسیرها و شناسه‌های حساس)
  - ثبت `trace_id`/`request_id` اختیاری برای همبستگی با لاگ‌های سرور
- حریم خصوصی:
  - عدم ارسال متن فرم‌ها/شناسه‌های بیمار/کاربر
  - نمونه‌برداری (Sampling) 10–20% کاربران برای کاهش هزینه/ریسک
  - Opt-in/Opt-out سازمانی در صورت نیاز سیاست


### نمونه‌برداری و ارسال
- Sampling پویا: افزایش در رخدادها/محیط Stage
- ارسال دسته‌ای (batch) با زمان‌بندی (هر 10–30 ثانیه) یا آستانه تعداد
- بک‌آف نمایی در خطاهای شبکه، صف موقت در حافظه


### داشبوردها و هشدارها
- داشبورد RUM:
  - توزیع LCP/CLS/INP، روند روزانه/هفتگی
  - نرخ خطاهای JS، خطاهای API به تفکیک مسیر/نقش
  - نرخ تکمیل فرم‌ها و زمان کار تکلیف
- هشدارها:
  - افت ناگهانی Web Vitals (LCP>2.5s, CLS>0.1, INP>200ms) در 5–10 دقیقه
  - افزایش JS errors یا 5xx/4xx بحرانی سمت کلاینت


### بازخورد کاربر (Feedback Loops)
- کانال‌ها:
  - ابزار بازخورد درون‌برنامه‌ای (NPS/CSAT کوتاه، 1–2 سوال)
  - فرم گزارش مشکل (با `trace_id`, زمان/صفحه، بدون داده حساس)
  - مصاحبه‌های دوره‌ای با کاربران کلینیکی منتخب (کیفی)
- زمان‌بندی:
  - NPS فصلی/نیم‌سالانه؛ CSAT پس از مسیرهای کلیدی (مثلاً پس از گزارش/پیش‌بینی)
- رسیدگی:
  - برچسب‌گذاری بازخوردها، اولویت‌بندی بر اساس اثر کاربر/بالینی
  - لینک به تیکت‌ها/نقشه راه و اطلاع‌رسانی وضعیت به کاربران گزارش‌دهنده


### یکپارچگی با Backend/Observability
- همبستگی RUM با متریک‌های سرور: Latency/Errors/RPS
- استفاده از `X-Request-ID` برای اتصال خطاهای کلاینت به لاگ‌های سرور
- گزارش‌های دوره‌ای (هفتگی/ماهانه) برای تیم محصول/فنی


### اجرای MVP
- گام 1: جمع‌آوری Web Vitals سبک (LCP/CLS/INP) + JS error count بدون PII
- گام 2: داشبورد پایه (Grafana/ابزار RUM) + هشدارهای ساده
- گام 3: فرم بازخورد کوتاه + فرآیند رسیدگی/اولویت‌بندی


### چک‌لیست سریع
- [ ] RUM سبک با Web Vitals و JS errors (بدون PII/PHI)
- [ ] Sampling و ارسال دسته‌ای با بک‌آف

- [ ] هشدار برای افت Web Vitals و جهش خطا
