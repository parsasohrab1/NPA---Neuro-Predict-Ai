## داده تست، فیکچرها، و ماک سرویس‌ها

### اصول داده تست
- استفاده از دادهٔ مصنوعی/ناشناس‌سازی‌شده؛ عدم استفاده از PHI/PII واقعی.
- تعیین Seed ثابت برای تکرارپذیری (faker/random).
- پوشش سناریوهای لبه: مقادیر مرزی، فیلدهای اختیاری، خطاهای رایج.
- جداسازی داده تست از داده توسعه/Stage؛ پاک‌سازی بین تست‌ها.


### فیکچرها (pytest fixtures)
- سطوح فیکچر:
  - session: راه‌اندازی یک‌باره (DB/Redis تست)
  - module/function: ایجاد داده و پاک‌سازی برای هر ماژول/تست
- نمونه فیکچرها (ایده‌ها):
  - db_session: سشن async موقت با rollback/teardown
  - user_factory: ساخت کاربر با نقش‌های مختلف (admin/doctor/nurse/viewer)
  - patient_factory: ساخت بیمار و سوابق پایه
  - auth_token_factory: دریافت JWT معتبر برای نقش‌های مختلف
  - redis_client_fake: نمونه Redis یا ماک برای کش


### الگوی ساخت داده (Factory)
- استفاده از الگوهای Factory:
  - patient_factory(first_name="Ali", gender="male")
  - medical_record_factory(patient=..., visit_date=..., biomarkers=...)
- مزایا: خوانایی بالا، کاهش تکرار، تغییر متمرکز داده پیش‌فرض.


### ماک سرویس‌ها (Service Mocks)
- اهداف: ایزوله‌کردن واحد تحت تست، حذف وابستگی‌های خارجی کند/ناپایدار.
- موارد رایج برای ماک:
  - integration_service (HIS/PACS/Webhook): پاسخ‌های قراردادی ثابت، خطاهای قابل‌پیش‌بینی
  - ai_model_service: خروجی‌های مدل (risk/confidence) با بذر ثابت
  - reporting_service: تولید PDF ماک (فایل موقت/بایت‌استریم کوچک)
  - cache layer: get/set با دیکشنری درون‌حافظه
- تکنیک‌ها:
  - monkeypatch/patcher برای جایگزینی توابع/متدها
  - ساخت کلاس Fake با همان اینترفیس (Dependency Injection)
  - ماک HTTP با `responses`/`httpretty`/`respx` برای تماس‌های بیرونی


### دامنه تست‌ها و داده مرتبط
- Patients API:
  - داده: 3–5 بیمار با اسامی/جنسیت/تاریخ تولد متفاوت، یکی با داده ناقص برای خطا
  - سناریوها: ایجاد/جستجو/به‌روزرسانی/حذف + RBAC (nurse/admin/...)
- Imaging API:
  - داده: متادیتای ساده مطالعه تصویربرداری، فایل ماک کوچک (نه DICOM واقعی)
  - سناریوها: آپلود/اعتبارسنجی/لینک به رکورد + خطاهای فرمت/حجم
- Predictions API:
  - داده: بیمار با حداقل یک رکورد بالینی معتبر
  - ماک مدل: risk/confidence ثابت (0.42/0.9) و نسخه مدل
  - سناریوها: مجوز doctor+، نبود رکورد → 400، موفقیت → 201 با بدنه کامل
- Reports API:
  - داده: پیش‌بینی کامل
  - ماک سرویس گزارش: PDF کوچک با امضای ثابت
  - سناریوها: تولید/دانلود + مجوزها
- Products API:
  - داده: چند محصول با `is_active` متفاوت
  - سناریوها: CRUD با admin، فیلتر `is_active`، جستجو `name/description`


### پاک‌سازی و ایزولاسیون
- تراکنش/rollback برای هر تست یا استفاده از پایگاه داده موقت (schema per test).
- حذف فایل‌های موقت (گزارش/تصویر ماک) بعد از تست.
- ریست کش/Redis بین تست‌ها.


### اجرای خودکار
- PR: فیکچرهای سبک، ماک سرویس‌ها، بدون وابستگی بیرونی
- Stage: تست با سرویس‌های واقعی/کانتینری (DB/Redis)، داده شبه‌واقعی
