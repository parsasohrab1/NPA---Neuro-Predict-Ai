## سرویس‌های خارجی: پرداخت، احراز هویت، ایمیل/SMS، آنالیتیکس

این سند گزینه‌ها، الگوهای یکپارچگی، امنیت، و راهبردهای پشتیبان برای سرویس‌های خارجی رایج را مشخص می‌کند.


### پرداخت (Payment)
- انتخاب‌های پیشنهادی (بسته به کشور/درگاه): زرین‌پال/زیبال/NextPay (ایران)، Stripe/Adyen (بین‌المللی).
- الگوهای فنی:
  - ایجاد تراکنش: `POST /payments/create` → دریافت `payment_url`/token
  - بازگشت کاربر: Callback/Redirect URL امن (HMAC امضا، state/idempotency-key)
  - وب‌هوک تأیید: Verify Server-to-Server (امضا/کلید عمومی)، پایداری با Retry/DLQ
  - Idempotency: کلید یکتا برای ایجاد/تأیید تراکنش‌ها
  - ثبت ممیزی: وضعیت، مبلغ، شماره پیگیری، کاربر/بیمار مرتبط (بدون داده حساس کارت)
- امنیت/انطباق:
  - عدم لمس/ذخیره اطلاعات کارت؛ واگذاری کامل به درگاه
  - TLS، امضای پیام، IP Whitelist برای وب‌هوک‌ها
  - لاگ ممیزی و نگهداشت طبق سیاست


### احراز هویت (Authentication/SSO)
- حالت فعلی: JWT داخلی (FastAPI) + RBAC
- حالت‌های توسعه:
  - OIDC/OAuth2 (Keycloak/Authelia/Auth0/Azure AD) برای SSO سازمانی
  - SAML (سازمانی) در صورت نیاز
- الگوها:
  - Authorization Code Flow (OIDC) برای وب
  - Token Introspection/Key Rotation برای امنیت کلیدها
  - Role Mapping به `UserRole` محلی
- نکات امنیتی:
  - انقضای دسترسی و Refresh Token، ابطال نشست‌ها
  - MFA برای نقش‌های حساس (Phase 3)، IP Whitelist اختیاری


### ایمیل/SMS
- ارائه‌دهندگان:
  - ایمیل: Mailgun/SendGrid/SES (بین‌المللی)، سرویس‌های داخلی بسته به زیرساخت
  - SMS: Kavenegar/IPPANEL (ایران)، Twilio (بین‌المللی)
- الگوهای ارسال:
  - Queue (Phase 2): ارسال آسنکرون با Retry/Backoff و DLQ
  - قالب‌ها: Templateهای ثابت با پارامترهای امن
  - محدودسازی نرخ (جلوگیری از اسپم/سوءاستفاده)
- موارد کاربرد:
  - اعلان گزارش آماده، هشدارهای طولی، بازیابی رمز، اعلان رخدادهای امنیتی


### آنالیتیکس (Analytics/Telemetry)
- انتخاب‌ها:
  - سمت‌کلاینت: Plausible/Matomo (حریم‌خصوصی‌محور) یا Google Analytics (در صورت اجازه)
  - سمت‌سرور: Event logging ساختاریافته + Elastic/ClickHouse (در آینده)
- اصول حریم خصوصی:
  - حداقل‌گرایی داده؛ عدم ارسال PHI/PII به سرویس‌های آنالیتیکس
  - ناشناس‌سازی/پسودونیم‌سازی شناسه‌ها
- الگوها:
  - Eventهای کلیدی: بازدید صفحات کلیدی، تکمیل فرم‌ها، ایجاد پیش‌بینی/گزارش (بدون داده حساس)
  - Opt-in/Consent در صورت نیاز سیاست سازمانی


### Observability و قابلیت اطمینان
- پایش:
  - نرخ موفق/ناموفق ارسال ایمیل/SMS، زمان پاسخ درگاه پرداخت، خطاهای وب‌هوک
  - داشبورد: خطا/موفقیت، تاخیر، Retryها، DLQ
- هشدار:
  - خطای وب‌هوک پرداخت/احراز هویت، جهش Error Rate ارسال‌ها
  - زمان پاسخ غیرعادی سرویس‌های کلیدی


### امنیت مشترک بین سرویس‌ها
- TLS همه‌جا، امضای درخواست‌ها (HMAC/JWT)، چرخش کلیدها
- محدودسازی نرخ، PoLP برای API Keys، ذخیره امن secrets در محیط
- ممیزی کامل عملیات حساس و نگهداشت معقول لاگ‌ها


### فازبندی پیاده‌سازی
- فاز 1 (MVP):
  - ایمیل پایه (بازیابی رمز/اعلان ساده)، بدون صف
  - بدون پرداخت (در صورت عدم نیاز تجاری)، احراز هویت داخلی JWT
  - آنالیتیکس سبک و حریم‌خصوصی‌محور (اختیاری)
- فاز 2:
  - صف ایمیل/SMS، وب‌هوک‌های امن، یکپارچگی پرداخت محدود (در صورت نیاز)
  - آنالیتیکس غنی‌تر با Eventها و داشبوردها
- فاز 3:
  - OIDC/SAML SSO، Role Mapping، MFA
  - انبار رویداد سمت‌سرور (در صورت نیاز تحلیل عمیق)


### Runbook اختلال سرویس خارجی
1) تشخیص: افزایش خطا/تاخیر در سرویس X (پرداخت/ایمیل/...)
2) ایزوله: Circuit Breaker فعال، کاهش ترافیک غیرضروری
3) صف/Retry: انباشت پیام‌ها در صف و Retry با Backoff
4) Failover: سوییچ به ارائه‌دهنده ثانویه (در صورت تعریف)
5) اطلاع: اعلام به ذی‌نفعان و ثبت رخداد
6) بازگشت: صحت‌سنجی، Drain صف‌ها، جمع‌بندی و RCA
